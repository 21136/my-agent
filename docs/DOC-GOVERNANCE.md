# 文档治理

本文约束仓库文档如何被阅读，不把历史材料提升为当前产品契约。

## 权威顺序

1. **当前实现事实**：当前分支源码、配置和测试；结论须说明检查范围。测试通过只覆盖实际运行的测试。
2. **用户确认的产品/安全决策**：由对应的短入口文档说明；若与实现不同，明确标为待实现/待核实，不宣称实现符合文档。
3. **专题说明**：描述指定能力，需核对源码和测试后才能作为现状依据。
4. **提案、计划、评审和历史记录**：仅保留在仍有决策或追溯价值时；其中的要求、测试数字、阶段状态不自动适用于当前版本。

## 当前项目阅读入口

项目工作以 `PROJECT.md`、`DESIGN.md`（必要时 `TECH-DESIGN.md`）和 `VERIFY.md` 为主要项目材料。`TASKS.md` 可能是旧项目遗留文件，不是本仓库当前进度真源，也不是普通项目权限门。验证报告必须列明实际范围，不得以文档存在、清单状态或一次定向验收推断全量通过。

权限理解应从当前意图、项目绑定/根路径、目标操作风险与确认策略出发；不要引用旧 phase 门禁、TASKS 队列或 runaway 自动化契约作为当前授权规则。

## 长任务边界

当前 Goal Runtime 是 P0 的轻量状态与预算骨架。它不等于旧 runaway/自动狂奔系统，不恢复 TASKS、阶段门禁、Progress Gate 或其验收承诺。只有源码及针对该能力的实际测试能证明当前行为；不得据此声称跨进程续跑、自动发布或完整生产验收。

## 维护规则

- 导航只链接现存、仍有用途的文档；移除文件时同步修复保留文档中的入口。
- 保留仍覆盖现存安全、运行架构、双车道和 managed 发布能力的说明；淘汰已完成且被源码/现行说明取代的实施计划、旧路线和状态快照。
- 标题、目录名、日期、历史测试数字都不是当前状态证据。
- 新增结论注明核对范围与未覆盖事项；禁止把未运行测试、未启动服务、未执行模型调用写成通过。
