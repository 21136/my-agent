# 项目保存的选定源码内容检查点

这是已批准 E1 方案中的工程步骤，不是 Git commit、合入稳定版、启用新版本或完整 AdoptionPlan 原生同意。

## 范围与数据

项目从当前只读审查和明确逐路径选择重新生成范围提案，核对 review/proposal 摘要。只保存所选 sandbox 普通文件的原始字节、Git blob 身份、SHA256、大小、模式，以及当时完整审查与请求。新增/未跟踪文件可保存原始内容，但不会因此获得 Git 基线、任务归属、稳定区不存在证明或合入资格；所选删除项暂不支持。所有历史/保护/归属/保留/缺失证明阻断继续存在。

单次检查点最多128路径、每文件4MiB、合计8MiB原始字节，整个规范JSON包最多16MiB。内容使用base64；不复制依赖、整个源码树、运行时或历史用户数据，不建立新Git仓库。包内完整审查会增加元数据占用，不是零成本去重。

工程存放位置固定为 sandbox 的 `artifacts/managed-source-checkpoints/<checkpointDigest>.json`。不写真实 prepared_empty 运行命名空间，不读取旧聊天、凭据或私有配置。检查点只提供逻辑隔离和内容完整性绑定，不声称私有ACL、同用户攻击者防护或同意来源认证。

## 桌面流程

已接入sandbox工程界面的已有逐路径选择（真实Electron原生呈现尚未验收）：核验范围后点击“保存选定源码检查点（不合入）”。宿主重新检查可信主页面、非fixture身份、固定关联根与新鲜完整审查；只有原生检查点专用确认通过，且确认后重新审查/捕获结果完全一致，才允许同步写入固定位置。取消或漂移不写入成功检查点。

确认仅绑定当前显示的源码内容检查点，不消耗/伪造完整合入同意，不调用旧一键合入接口。渲染器无权传入根、源码字节、文件名、报告或确认结果。网页环境没有兜底写接口。

编辑路径、重读或清空会使页面旧结果失效；但在原生确认打开后，渲染器的改选不构成宿主操作取消或回滚。已经确认并保存的旧范围检查点是历史材料，不能代表页面新选择。任何后续合入都必须重新绑定当前完整 AdoptionPlan 和源状态。

## 文件语义与恢复边界

单一规范JSON加LF，内容地址文件名，排他新建，不覆盖既有文件；文件fsync后通过同一描述符与路径重读校验才返回成功。链接、重解析点、别名、硬链接源码/包、源字节/模式漂移和超限均拒绝。检查点历史读取校验包内完整绑定，但不证明现在源码仍匹配、用户曾确认或此前写入一定已耐久。

错误/中断留下的部分文件保留，不自动清理，也不将同名既有文件当作成功回执。文件fsync与重读不等价于跨平台目录项断电耐久承诺。内容检查点不是可执行合入事务包，不交给现有 clean-only recorded merge 执行器。

## 验收与后续

验收记录分别区分定向模块/可信桥接/组件测试与真实Electron原生验收。单元测试、伪原生回调或HTTP组件测试不算真实原生确认/合入/启用验收。

后续仍需安全的脏 stable 保留合入、完整 AdoptionPlan 精确范围原生确认、操作态命名空间与可信上下文、项目执行实际合入及合并后重建封存、全写路径fencing/空库初始化/激活/恢复/LKG，以及独立安全provider适配和预算。实际项目模型只允许 `0x567-flash`；本步骤不调用模型。

存放区同时限制最多8个保留文件、合计32MiB逻辑文件字节。未知条目、链接、超出预算时停止，不自动删旧检查点或部分文件。F:当前128KiB分配单元会产生额外簇占用，文件簇取整开销上界另计不到1MiB，目录/文件系统元数据不包含在这一估算中；这仍不是双版本总占用。
