# 狂奔 R6：可靠性与长跑演练

> 版本：0.1.0 · 2026-08-26  
> 状态：实现基线

R6 的目标不是让狂奔“永不停止”，而是让它在长时间运行、进程重启、连接断开、验证失败和资源耗尽时，都能做到：不重复执行、不丢失上下文、不伪造完成、可判断是否需要人工处理。

## 1. 可靠性目标

一次狂奔作业必须满足以下不变量：

- 同一项目同一时刻最多只有一个执行者；
- 执行者退出后，其他进程可以识别过期租约并安全接管；
- 活跃执行者持续刷新租约，不能被误判为已失活；
- 任务切换、验证开始/结束、暂停和发布确认前后都保留检查点；
- 重启或断线恢复只能从检查点继续，不能重新执行已确认的不可重复动作；
- 工具轮次、修复次数、验收证据和暂停原因可追溯；
- 长跑达到时间、轮次或资源预算时进入可解释的暂停，而不是返回“完成”。

## 2. 故障矩阵

| 场景 | 预期行为 | 验收信号 |
|---|---|---|
| 两个进程同时恢复同一项目 | 只有一个获得租约，另一个不执行 | `runaway_duplicate` |
| 执行者正常心跳 | 租约持续有效 | 心跳时间持续更新 |
| 执行者崩溃 | 租约超过 TTL 后可接管 | 新执行者获得新 token |
| WebSocket 断开 | 作业继续或按检查点恢复 | 不产生假完成 |
| 侧车进程重启 | 从持久化 checkpoint 恢复 | 任务指纹保持一致 |
| 验证失败可修复 | 进入修复并重新验证 | 修复次数递增 |
| 相同失败重复出现 | 暂停并给出原因 | 错误指纹保持一致 |
| 达到运行预算 | 暂停并记录预算原因 | 不进入 `completed` |
| 最终发布确认 | 仅人工确认后完成 | 绑定当前发布 revision |

## 3. 跨进程租约协议

租约文件位于项目 `.plan-agent/runaway-lease.json`，通过原子创建抢占。文件至少包含：

```json
{
  "project_id": "demo",
  "pid": 1234,
  "token": "…",
  "acquired_at": "…",
  "heartbeat_at": "…",
  "ttl_seconds": 120
}
```

释放租约必须校验 token，不能删除其他执行者刚刚接管的新租约。发现文件已存在时：

1. 能读取且心跳未过期：拒绝接管；
2. 心跳已过期：原子替换为新 token 后接管；
3. 文件损坏：保守地按未过期处理，记录可诊断错误；
4. 进程退出无法清理文件：依赖 TTL，而不是依赖退出钩子。

## 4. 长跑预算与恢复演练

R6 将运行预算拆成三个独立维度：总墙钟时间、累计工具轮次和自动修复次数。任一预算耗尽都必须写入暂停原因和最近检查点。预算不能因为 WebSocket 重连或进程重启而归零。

演练测试至少覆盖：双执行者竞争、过期租约接管、活跃租约不误接管、token 保护释放、checkpoint 重启恢复、重复验证失败暂停和预算耗尽暂停。

## 5. 发布标准

R6 完成标准：

- 跨进程租约具备原子抢占、TTL、心跳和 token 安全释放；
- 故障矩阵中的核心场景有自动化测试；
- 现有 R1～R5 狂奔与制品测试继续通过；
- 至少完成一次模拟长跑演练，证明恢复后任务指纹、修复次数和验收证据不丢失；
- 文档、日志和用户界面不把“租约”“TTL”“checkpoint”等内部术语当作用户操作要求。

R6 不自动放开外部写入、发布、推送或不可逆操作；这些仍遵守 R1～R5 的人工决策边界。
