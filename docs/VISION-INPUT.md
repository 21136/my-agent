# 图片识别输入设计

> 版本：0.1.1 · 2026-08-24
> 状态：已实现

## 目标

用户把 PNG、JPEG、WEBP 或 GIF 拖入聊天框并发送后，当前回合直接把图片作为多模态输入传给支持视觉的模型。文本、代码和 PDF 继续沿用现有附件路径与工具读取链路。

## 交互

- 拖入图片后仍先显示附件 chip，点击发送才发起回合。
- 图片 chip 标记「可识图」；不支持视觉的模型显示「当前模型不支持识图，请切换模型」而不是假装看过图片。
- 图片正文不写入 `messages.jsonl`、日志或 WebSocket；历史只保存文件名、路径、大小和 MIME 元数据。
- 同一回合可以发送文字、图片和其它附件；模型收到文字块与图片块。

## 技术方案

1. `file_stage` 识别允许的图片 MIME，并在附件元数据中标记 `image_input`。
2. 用户消息仍以可回放的 `[附件]` 文本保存；构造 LLM 请求时解析图片附件引用。
3. 对支持视觉的模型，将可读图片转成 OpenAI-compatible `data:<mime>;base64,...` 图片块。
4. 对不支持视觉的模型，保留原附件文本，不发送图片二进制，并返回明确能力提示。
5. 图片只允许 agent workspace 或已授权 host scope 内的可读路径；敏感路径继续拒绝。

## 模型能力

模型注册表新增 `supportsImageInput` / `supports_image_input`。内置 `0x567` 模型默认开启；DeepSeek / Sophnet 默认关闭，避免向不支持视觉的端点发送非法 payload。自定义模型需要显式配置为 `true`。

## 限制

- 单文件沿用 32 MB 暂存上限；发送给模型的图片上限为 8 MB。
- 仅支持 `image/png`、`image/jpeg`、`image/webp`、`image/gif`。
- 图片读取或编码失败时，回退为附件路径说明，不中断整轮对话。

## 验收

- 图片附件元数据包含 `image_input: true`。
- 支持视觉模型收到 `content: [{type: "text"}, {type: "image_url"}]`。
- 不支持视觉模型收到纯文本附件说明。
- 图片不进入会话正文和日志。
- 现有文本附件、拖放和工具调用测试保持通过。
