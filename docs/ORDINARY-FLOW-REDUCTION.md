# 普通模式流程减负（提案 · 未实施）

> 状态：**proposal only**（2026-09-12）  
> 范围：Desktop / CLI 的 **普通模式**项目流程；不改狂奔 v2 主状态机。  
> 依据：`0x567-flash` 普通模式写项目探测、计划门实机卡点、Desktop mockup/真机审阅。  
> 相关：`PROJECT-MODE.md` §4 计划确认门 · `DESKTOP-TEXTBOOK-FLOW.md` 五段闸门 · 现网已合入的「直接实现话术自动确认」属过渡补丁。

---

## 0. 一句话

普通模式应提供两条**显式入口**：`规划后开工` 与 `直接实现`；小项目用轻模板；确认合并为「关卡」而不是「一路点同意」。不要继续用话术特例堆在计划门上。

---

## 1. 问题（已观测）

| # | 现象 | 证据 / 影响 |
|---|------|-------------|
| P1 | 「直接做」与默认「先 plan_partner → draft 门」打架 | 空白项目探测：模型判不必规划仍调 `plan_partner`，零业务代码；靠话术自动确认是补丁 |
| P2 | 普通 / 狂奔双轨叠在同一套七文件 + 阶段上 | 同一卡点常要写特例；测试面与心智膨胀 |
| P3 | 确认层叠：计划卡 + tool confirm + shell 分类 + 口头再问 | `verify.py` 曾被标 `other`；用户体感「一路点同意」 |
| P4 | 小项目也背完整制品链 | 新建即 PROJECT/DESIGN/TASKS/VERIFY…，文档完整度 > 交付速度 |
| P5 | Desktop 状态噪音盖过下一步 CTA | 侧栏统计偏多；「确认开工 / 开始任务 / 跑验收」不够醒目 |

---

## 2. 非目标

- 不废除计划确认门（正经项目仍要有闸）。
- 不在本提案重写狂奔 v2 checklist / harness / bug-fix。
- 不一次砍掉七文件真源；先做 **档位**（轻 / 标准），再谈合并文件。
- 不把「直接实现」做成隐式永久免确认（仍要可审计的会话标记）。

---

## 3. 目标体验

### 3.1 两条显式入口（产品面）

新建或打开项目后，用户选其一（Desktop 主 CTA；CLI 等价命令）：

| 入口 | 用户心智 | 系统行为 |
|------|----------|----------|
| **规划后开工** | 先对齐范围再写码 | 保持现流程：出计划 → 计划确认卡 / `项目 确认` → implementation |
| **直接实现** | 现在就改文件跑验收 | **跳过** plan_partner 预拉起；自动 `confirmed` + 进入可写码阶段；本回合禁 plan_partner；overlay 明确「已确认、直接写码」 |

> 现状：仅靠自然语言命中「直接实现」标记。提案要求变成 **显式入口**，话术匹配降为兼容层。

### 3.2 确认合并原则

1. **一关一确认**：计划门通过后，同回合不再口头要「确认开工」。
2. **项目内验收默认免确认**：`pytest` / `python verify.py`（及 ENV.md 登记的 quality commands）在 project cwd 下免确认。
3. **危险动作仍确认**：install、网络写、删目录、非 loopback 预览、`gh_pr create`、`git_push` 等。
4. **工具确认文案短**：只保留动作摘要，不重复粘贴计划门说明。

### 3.3 模板档位

| 档位 | 何时 | 制品 |
|------|------|------|
| **轻量** | 直接实现 / 用户选「小项目」 | `PROJECT.md`（短）+ `TASKS.md` + `verify.py` 约定；MAP/DESIGN/RELEASE 可延后生成 |
| **标准** | 规划后开工 / 正经项目 | 维持现七文件 + VERIFY 矩阵 |

轻量档仍受 project 根与写码范围约束；升到标准档时补齐文件，不重置进度。

### 3.4 Desktop CTA

侧栏/顶栏优先展示**下一步唯一主按钮**：

- draft + 规划轨 → **确认开工**
- draft + 直接实现入口已选 → 不显示确认卡，直接显示 **实现中 / 跑验收**
- implementation → **跑验收**（点到 ENV quality / verify）
- 次要信息（会话统计、服务）默认折叠

## 6. 验收标准（提案级）

1. 空白项目点 **直接实现**，一轮内能写出业务文件 + 跑过 verify，且 **零次** plan_partner、零次「请确认开工」口头门。
2. 点 **规划后开工**，行为与今日规划轨一致（仍须确认卡）。
3. 轻量模板新建，初始文件数显著少于标准七文件；可升档。
4. 项目内 `pytest` / `python verify.py` 不弹工具确认；`git push` / `gh pr create` 仍弹。
5. 狂奔路径回归：既有 runaway v2 测例不因普通模式入口而红。

---

## 7. 已决（2026-09-12 拍板）

1. **直接实现入口范围**：仅 `requirements` + `draft`/`plan_dirty` 可一键进入写码。`documentation` / `design` 不走直接实现冲刺（仍用既有确认设计 / 开始任务）。
2. **轻量档门控**：跳过 L2 stale 检查；Progress Gate 只要求 `TASKS` + `verify` 证据（不因缺 DESIGN/MAP 挡写码）。升标准档时再补齐并启用完整 L2。
3. **Desktop 双 CTA 位置**：每个 **draft** 项目顶栏常驻「规划后开工 / 直接实现」，确认前可切换；确认后顶栏改回下一步主 CTA。
