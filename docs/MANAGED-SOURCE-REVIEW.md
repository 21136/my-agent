# 管理源码范围审查（只读）

本页说明 sandbox 中现有「壳开发预览 → 只读源码审查」的可浏览范围界面。它是 E1 正式采用流程的工程环节，不是另一套合入入口。稳定主壳不会因这些源码编辑自动更新。

## 界面做什么

- 展示完整审查摘要及两边 HEAD、分支、原始 index SHA256、工作区根身份。
- 分类查看稳定区**待保留审查**、sandbox **待确认归属**、全部历史触及路径、merge-base 到 sandbox HEAD 的净树差异、两侧排除路径、阻塞项以及提交元数据。
- 按路径或摘要做大小写不敏感的字面搜索；分页只影响显示，不删减报告，也不改变任何阻塞项。
- 展开条目可看完整原始字节 SHA256、HEAD/index/working blob OID、模式及状态等报告已有字段。缺失字段不会被补成干净或已确认；完整原始 JSON 保留在折叠区。
- 受保护/范围外排除项只来自已有名称与分类元数据；界面不读取其内容，也不额外读取 blob、旧聊天、密钥或私有配置。
- 刷新开始、获取失败及网页环境会清除旧分类视图，不能把上次报告误作本次审查。

## 不做什么

浏览、搜索、翻页、展开不构成任务归属、保留结果或原生同意，不会暂存、提交、stash、合并、同步、启用旧合入按钮或启动候选。

报告始终保持 `execution=false`、`readyForMerge=false`、`readyForLaunch=false`。净树差异不是预期合并结果，历史触及范围不是获准交付范围；原始字节差异也不是 Git clean-filter/EOL 归一化后的 dirty 状态。

真实报告仍只通过已有 Electron 可信主页面的无参数 IPC 获取，根路径由宿主决定。网页没有网络/Git 采集兜底。独立组件验证页若使用历史报告，必须明确标注历史时间和仅组件证据，不作为当前范围确认或 Electron 原生验收。

## 后续仍由工程完成

准确的任务归属/稳定区保留与项目控制的选定检查点、完整原生范围确认、命名空间操作态、真实项目执行合并及合并后重建/封存、写入 fencing/空库初始化、激活/维护恢复/LKG 仍未由该界面实现。安全私有 provider 路径和明确预算也仍独立待办，真实调用只能使用已授权的 `0x567-flash`。

本环节不复制依赖、运行时或源码树，不创建测试 Git 仓库，不清理既有夹具/备份；不能据此估算整套双版本的最终空间。

### 两区逐路径对照

两侧允许源码清单可以按相同路径并排查看。只有两边都具备合法完整的工作文件 SHA256 时，才标注「原始字节相同/不同」。相同仅指字节，不能推导 HEAD/index/暂存/模式相同，更不能推导归属、可覆盖或可合入。某侧没有清单条目表示清单未列出，不等于文件不存在；报告明确的工作文件缺失与哈希未知分别显示。

## 2026-10-24：逐路径范围声明

相邻新增的范围选择区允许明确声明 sandbox 路径，项目经可信宿主重新采集并核对同一审查摘要后，返回不执行的完整范围提案。见 [MANAGED-SOURCE-SELECTION.md](MANAGED-SOURCE-SELECTION.md)。默认不选择任何路径、稳定区条目全部列为保留要求；原有阻断不清空，声明不等于归属证明、保留收据、原生同意或合入权限。只读审查浏览区本身仍不产生选择或执行权。
