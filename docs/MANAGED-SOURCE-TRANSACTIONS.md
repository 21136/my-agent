# 源码采用事务（E1 执行协调层）

本模块实现“写入前记录意图 → 项目执行器做一次源码合并 → 记录退出结果 → 独立核对合并结果 → 保存回执”的协调层。

## 当前可用范围

- `desktop/launcher/managed-source-journal.mjs`：首个源码采用操作的单次、追加式事务日志。
- `desktop/launcher/managed-source-transaction.mjs`：精确计划、摘要确认、可信执行适配器与结果回执的协调。
- 入口是内部 Node 模块，不是新增给用户执行的 CLI/IPC，也没有接到旧的自动暂存/储藏采用流程。
- 正式执行适配器尚未实现。测试里的回调和一次性 Git 仓库不具备正式运行身份，不得替代它。

## 安全边界

计划需要绑定安装/命名空间/审查摘要、稳定与实验源码身份、精确交付路径及前后哈希、预期合并树和保留状态摘要。存在 blocker、错误确认、未知字段或摘要改变，必须停止；只读报告自身不是授权。

执行器是主进程内可信代码，负责重新检查实际源码、完整范围、归属、冲突和保留状态。它不能来自网页、插件或用户拼装的 JSON。协调层不能独立证明一个任意回调说的“成功”是真的；因此不会提供任意回调转正式采用的入口，也不会为缺失的正式适配器设置默认实现。

源码合并退出 0 仍不是完成：必须再次核对真实合并提交、两个父提交、精确路径、结果树及保留状态。该回执也只证明源码阶段，不表示构建、数据租约、发布激活或模型调用通过。

## 日志与中断

调用者提供既有且归属已验证的日志目录。该目录的首个事务以排他创建的 `managed-source-transaction.jsonl` 占位，写入意图同步后才能调用合并；退出回执同步后才能开始结果核验。使用单文件而非每一步一个小文件，避免在 128 KiB 分配单元的盘上无谓放大。

这个首事务日志永久单次使用。另一个进程或后续重启不能接管它、重试合并、删锁或自动回滚；需要另行实现并审查恢复/后续操作协议。已存在但未完成的记录进入维护状态；截断、错误身份、无效顺序/摘要链等材料不能被识别为成功。

文件同步与摘要链不等于 exFAT 断电验收，也不防拥有同权限的恶意进程重写整个目录。本阶段没有操作系统级隔离、应用数据写入租约或自动恢复承诺。

## 仍须完成的正式采用链

1. 完整归属/保留审查、可信正式执行器和原生精确范围确认。
2. 项目对真实源码执行合入，取得真实结果树和事务回执。
3. 从实际合并后的稳定源码重建发布，验证来源与只读候选。
4. 单写者 fencing、空库初始化、持久激活/维护恢复和原生生命周期验收。
5. 模型集成另行完成私有凭据适配与预算限制；只允许已授权的 `0x567-flash`。

现有真实命名空间仍保持空准备态，旧聊天/凭据不读取、不复制、不迁移。不能把本阶段交付说成“只剩用户真实使用验收”。

### 读取日志不是恢复授权

`readManagedSourceJournal` 返回的是摘要链与事件顺序校验后的**历史记录**，不重新核对当前源码，也不证明每次 `fsync` 曾经成功。特别是：完整的 finish 行可能已经写入，但随后同步报错；执行调用此时必须失败，而后续读取仍可能看见那条历史行。这样的材料不能直接授权恢复、激活或重试。正式恢复需要独立重核实际源码、事务、发布与数据状态；本阶段没有这一恢复协议。

### 本轮执行层尚缺的持久材料

首事务日志保存计划/审查摘要绑定与步骤回执，**不保存完整源码审查包和完整 AdoptionPlan**。正式执行适配器在真实写入前还必须把完整计划、精确范围、来源身份与原生确认材料持久保存，并由恢复协议独立核对；不能只靠当前日志中的摘要恢复执行。本阶段没有实现这条正式适配链。
