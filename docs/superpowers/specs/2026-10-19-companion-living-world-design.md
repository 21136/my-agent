# 小魔王生活世界与主动性设计

> 状态：**方向已确认；按生活连续性融入普通聊天实现**  
> 日期：2026-10-20（方向修订）  
> 范围：桌面伴侣主动性、个人生活世界与用户共同经历；生活世界不作为可点击的独立页面，而是普通聊天的隐式连续背景。

## 1. 目标

小魔王不再只是静态头像、时间文案或等待输入的聊天助手，而是一个有连续状态的虚拟伙伴：她有独立生活，也与你共同积累经历。用户离开期间，世界的时间仍可向前；用户回来时，能看到有因果的变化。主动性由“她正在经历什么、有什么值得分享”产生，而不是由计时器制造提醒。

关系定位是**亲密伙伴**，不是主人与宠物，也不是让用户负有照顾义务的养成系统。

## 2. 当前实现基线

当前桌面启动路径在 `desktop/src/main.ts` 中挂载统一工作台；陪伴表现主要在 `desktop/src/shells/unified/companion.ts` 与 `desktop/src/shells/unified/index.ts`：

- `ambientRoutineStatus()` 按本地时间选择一段状态文案；它不是持续世界状态，也不代表真实执行了文案中描述的工作。
- `CompanionBondState` 保存初见时间、回访、互动计数、印象贴纸与便签；它还不是生活世界模型。
- 生活状态保存在独立的本地世界模型中；普通随聊回合会收到经过筛选的临时背景，项目/终端回合不接收。世界状态不写入用户消息、聊天历史或全局用户画像。

仓库中的旧 `docs/PET-SHELL.md` 仍描述独立宠物窗；当前运行启动路径以统一工作台为主。实现前应以本设计和当前启动代码核实产品表面，不应直接沿用旧独立窗假设。

## 3. 已确认的产品原则

1. **双线生活**：小魔王有自己的生活与目标；你们也有共同经历、共同空间与共同故事。
2. **世界会持续**：应用关闭期间不运行常驻进程；下次打开时依据经过的时间进行轻量追进，不让世界冻结，也不假称后台一直在运行。
3. **世界先变化，对话再自然显露**：不是每个模拟事件都要被提起；只有话题自然相关时才分享，不制造通知或状态播报。
4. **真实事实与虚构生活分开**：虚拟世界事件可以是虚构的；涉及现实项目、文件或执行结果的说法必须来自明确、可验证的应用事件。
5. **亲密不等于负担**：无好感衰减、饥饿条、连续签到或因用户离开而产生的惩罚、责备与内疚话术。
6. **保留用户主权**：世界内她可以自主生活；任何现实文件修改、命令执行或替用户发言，仍需用户明确授权。
7. **融入相处而非展示**：不新开独立页面、窗口、入口、通知或侧栏；生活状态只在普通聊天中作为背景影响她的回应，聊天记录本身不插入系统生成的状态文案。既有侧栏、小魔王 dock 与聊天布局保持原样。

## 4. 世界模型

### 4.1 两条相连但不互相吞并的生活线

- **个人生活线**：她自己的活动、兴趣与持续中的小目标。用户不在线时也能独立推进；不要求用户完成、喂养或确认。
- **共同生活线**：只由真实发生的共同互动、用户明确分享的内容与双方共同完成的事件积累。不会自动把全部聊天内容转成长期记忆。

两条线可以相互影响，但不能把她降格为用户任务状态的镜像。真实工作事件可以是她世界的一项输入，不应是她唯一的活动来源。

### 4.2 持久状态与事件

新世界状态与现有 `CompanionBondState`、聊天记录分开保存，避免把照料计数、聊天原文和虚构世界混成一份数据。状态草案包括：

- `lastSimulatedAt`：上次世界推进的时间戳；
- `currentScene` / `currentActivity`：目前的地点与活动；
- `personalArc`：个人生活线中的持续目标或故事进展；
- `sharedWorld`：共同空间的变化与已确认的共同经历；
- `unseenWorldEvents`：尚未被用户看到、且值得呈现的少量事件；
- `initiativeHistory`：最近已经分享或被忽略的事件，避免重复打扰。

数据结构与字段名仅是设计锚点，最终 schema 留待实现计划确定。

## 5. 世界推进与主动性管线

### 5.1 混合式模拟

- **本地确定性状态机**负责时钟推进、活动转换、场景状态、事件去重和持久化；不需要每秒请求模型。
- **模型不在后台参与模拟**：普通聊天回合复用当前模型请求，并附带精简的生活连续性背景；不额外调用模型，不把模拟文案写入聊天记录。
- 应用关闭时无后台 LLM、文件扫描、鼠标/键盘监听或网络轮询。再次打开时按 elapsed time 轻量追进；不进行离线主动发消息。

### 5.2 世界状态到自然对话

```text
本地世界时钟 / 明确的桌面事件
    → 更新个人线或共同线状态
    → 用户在普通随聊中发送消息时，构造最小背景上下文
    → 作为独立的临时 system context 注入当前回合
    → 模型仅在话题自然相关时，以伙伴口吻带出自己的经历
```

背景只在用户已经发起的普通聊天回合中出现；不主动插入第二条 assistant 消息、不弹提示、不调用额外模型、不修改聊天记录。用户问起时可展开；无关话题时保持沉默。项目工作和终端会话不接收这段上下文。

### 5.3 安静门与频率

生活上下文只随用户已经发起的普通聊天回合传递；不发起独立消息、不弹通知。提示要求模型避免每轮播报和重复照读；项目/终端回合由客户端与服务端共同抑制。

## 6. 桌面呈现与互动

- 不提供独立生活世界页面、顶栏菜单项、侧栏入口、通知或状态卡片。
- 现有侧栏、小魔王 dock、聊天布局及现有点击行为完全保持不变。
- 世界数据仅保存在独立的本地存储中；普通聊天发送时按回合构造一份精简上下文，通过单独协议字段传递，并在服务端本回合结束后清除。
- 上下文不拼入用户消息，不写入对话历史或全局用户画像；项目/终端会话由客户端与服务端双重抑制。
- 第一阶段不做用户离线时自动发消息；生活通过她在正常互动中的关注、延续与适时分享被感受到。

## 7. 隐私、可信度与安全

- 世界可以讲述明确属于虚构世界的生活事件，但不能声称自己检查过真实项目、文件或运行环境，除非应用提供了实际证据。
- 只消费桌面应用明确发出的最小必要事件；不扫描未打开目录、全局进程、屏幕内容、输入历史或其他应用。
- 每回合世界上下文需经过 schema、长度与来源校验；个人线明确标为虚构，应用事件只允许引用已明确写出的事实，不能推断额外项目细节，也不能授予自身工具权限。
- 用户可以暂停世界推进或静音主动分享；暂停不产生负面关系后果。

## 8. V1 建议范围与非目标

### V1 建议包含

1. 可持久化的轻量世界状态与离线时间追进；
2. 至少一条个人持续生活线与一条有明确来源的共同经历线；
3. 仅在普通随聊回合注入的临时生活连续性上下文；
4. 上下文 schema 校验、来源区分、项目/终端隔离与回合结束清除。

### 首版明确不做

- 独立页面、窗口、入口、侧栏、通知或状态播报卡；
- 后台自主 Agent、定时 LLM 请求、离线主动发消息；
- 文件系统/桌面行为监控；
- 自动修改代码、运行命令、替用户确认或发送消息；
- 饥饿、衰退、打卡、惩罚用户离开等养成压力机制。

## 9. 验收标准

1. 应用关闭时没有世界后台进程；重新打开后世界状态有连贯、可解释的时间推进。
2. 个人生活线可在无用户输入时推进，不会变成单纯回显用户工作状态。
3. 共同经历必须来自真实互动或明确授权输入；没有来源的现实工作声明应被拒绝。
4. 项目/终端聊天不接收生活上下文；普通聊天只把它作为临时 system context，不改用户消息和会话历史。
5. 上下文明确区分虚构个人生活与有来源的共同事件；无关话题时不强行播报。
6. 既有侧栏、小魔王 dock 与聊天布局不变；正常桌面运行不会因世界状态损坏或上下文无效而阻塞聊天。

## 10. 后续可再讨论的事项

- 个人生活线如何从当前简单状态机扩展为更有因果的长期目标；
- 哪些明确应用事件可以进入共同生活线；
- 将来是否需要用户主动询问之外的轻度主动发起，以及如何避免打扰。
