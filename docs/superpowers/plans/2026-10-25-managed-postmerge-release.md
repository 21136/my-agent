# Managed postmerge input, build and seal continuation

Continuation of continuous-closeout Task3 and the approved E1 design. All coding, generated sources, builds and isolated Git experiments remain under the existing sandbox. Preserve stable source/Git and the real prepared_empty namespace. No installation, credentials, model request, data import, source promotion or native application launch.

1. Parent: materialize the exact verified committed-source blob payload into a new bounded owned build operation; durable intent and manifest precede writes, input inventory is immutable, interrupted/unknown operations retained. Reuse the existing v2 source receipt and pre/post source guards.
2. 6luna builder worker: configless Node/Vite/TypeScript target builder consuming only the materialized source tree and a separately pinned existing sandbox dependency installation. Never execute repository configuration/scripts, load dotenv, install dependencies, launch Host/sidecar, or borrow stable dependencies. Pin source package/lock against toolchain declarations and pin toolchain bytes before/after. Persist exact output inventory only on success.
3. 6luna seal worker: independent production-schema release artifact sealer/verifier, consuming verified materialization and build records; copy only the declared runtime payload, verify hashes and exact directory inventory, exclusive publish and no overwrite/cleanup. Bind source/merge/build/toolchain provenance. Fixture release identities remain incompatible. Release sealing alone never permits launch.
4. Parent: wire explicit materialize/build/seal/verify CLI commands. Run a tiny actual Git/Vite build/seal integration, source/output/tamper/partial-operation refusal regressions, relevant existing source gates and scoped type checks. Independent 6luna review then stable/source/Git/namespace protection and storage measurement.
5. Continue production context/write-lease/lifecycle only against the E1 contract. No metadata-only scaffolds count as native activation. Keep real namespace empty until the complete writer/init and state transitions exist.

Ruling: source/build artifacts live in sandbox/artifacts/managed-postmerge-builds/<operation UUID>, separate from real namespace and user data. Maximum four operations; logical and 128KiB-rounded file allocation budgets are enforced before materialization/copy, and unknown/partial state fences reuse. Existing dependency installation is read-only and hash-bound, never copied or represented as immutable by a lockfile alone.

Ruling: the final fixed build policy is configless_snapshot_v2, including parent-bound record identities, verified byte caches and the Windows compiler file guard. Historical configless_v1 operations remain preserved for accounting only. Explicit main/preload, renderer entry and static public assets are inputs; candidate Vite/npm scripts are data only. New release artifact mode managed_postmerge_release_v1 is separate from E0 launcher_fixture_v1. readyForLaunch remains false: runtime binding, empty-store lease/initialization and native lifecycle are separate required gates.

Integration contract: operation holds intent.json, source.json, materialized.json, toolchain.json, build.json, source/ and build/, then release/ after sealing. Every JSON record is canonical LF JSON and digest-bound. Build outputs paths are relative to build/ (desktop/dist-electron/main.js, desktop/dist-electron/preload.js, desktop/dist/index.html and dependent assets). Shared schema/helpers are managed-build-records.mjs; workers must not weaken them or modify another owner's files.
