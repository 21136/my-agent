# Project-local Managed Preparation Design and Plan

**Status:** User approved project-contained runtime layout and instructed implementation on 2026-10-24. This is a bounded extension to existing namespace preparation, not production adoption/activation acceptance.
**Goal:** Allow explicit project-local preparation on this exFAT workspace; measure true storage cost without duplicating a full checkout/dependency tree per release.

## Binding decisions
- Edit code only in sandbox. Initial runtime anchor is exactly `<sandboxSourceRoot>/.managed-runtime/<installationUUID>`, still inside the user's project and owned sandbox. No new runtime tree outside sandbox in this milestone. This is NOT a dependency, build cache, fixture or disposable artifact directory.
- Introduce distinct `managed_project_local_v1` mode with explicit `security_policy: logical_separation_only`, credentials forbidden. NTFS/private ACL mode remains unchanged; no auto-fallback from private preparation failure.
- Explicit commands `--prepare-project <stableRoot> <sandboxRoot> <UUID>`, `--check-project <stableRoot> <sandboxRoot> <UUID>`, `--inspect-project <stableRoot> <sandboxRoot> <UUID>` bind expected trusted roots before reading the new marker. No generic marker-mode autodetection or arbitrary path.
- Same fixed empty layout as existing preparation: launcher, state, releases, host/state, host/profile, host/workspace, data/store. Exclusive UUID creation; canonical bounded marker; strict fields; source/root/layout/digest binding; no links/reparse or preexisting UUID reuse; local fixed NTFS/exFAT only, no network/removable/unknown volume. No ACL assurance or same-user malicious-process isolation claim.
- Source nesting exception is ONLY the reserved `.managed-runtime` subtree of sandbox, never code/data/fixture/artifacts or arbitrary roots. Add sandbox Git ignore and explicit name-only protected exclusion from source preflight. Project build paths and source capture allowlists already exclude this reserved root; tests must prove this. Normal Git merge/sync does not remove ignored runtime data; removing worktree or clean -fdx remains explicitly prohibited, never implement automatic cleanup here.
- Runtime mode is preparation-only: ready_for_launch=false. It must refuse any populated runtime/data; it is not the eventual runtime health command. No candidates, model requests, old data reads, migration, staging/commits/merges or activation. Existing project-managed adoption requirement remains, with source review/provenance, lease/fencing and recovery still required before real adoption.
- No full-source/dependency/runtime copy during preparation. Metadata inventory reports logical bytes and per-file allocation-unit estimates separately. No implicit backup deletion, retention cleanup, dependency linking, migration or compression. Version growth estimates must distinguish sealed app payload from shared verified external runtimes and additional full development lanes.

## Rulings
- User's latest project-local request supersedes mandatory AppData location for this new mode only, not the private-mode validation rules. exFAT supports logical directory separation but not the private ACL guarantee.
- Use sandbox-root reserved runtime initially to honor original sandbox-only write boundary. A future source promotion must not relocate/delete it implicitly; installation path migration requires explicit design.
- No automatic version pruning is added before active/LKG/lease identities exist; deleting a recovery or referenced runtime to hit a numeric limit would be unsafe. Current work prevents duplication at preparation and exposes storage truth; a future publishing budget gate is separate work.
- Independent review ruling: interrupted preparation deliberately preserves partial UUID directories and refuses reuse; it is fail-closed, not a failure-atomic activation transaction. Documented recovery is retain failed evidence and choose a fresh UUID; deletion/reuse requires separate exact-path review/authorization. This is accepted within empty provisioning scope, not production crash recovery.
