## 自检发现并修正的问题

1. **完整候选不是单进程。** 启动描述调整为多个 runtime 和无环组件依赖图，支持 Python 内核、Node 服务、Electron 桌面及 adapter；单个 Vite ready 不代表应用 ready。
2. **过早推进 last-known-good 会破坏恢复。** 观察期只切 active，保留旧 last-known-good；观察通过后才推进。冷启动也核对数据和写租约，不能盲目启动旧程序写新数据。
3. **普通 before-hash 检查存在写入竞态。** 要求同一排他文件操作内校验并写入；无法取得所需锁就拒绝。单写租约不代替外部编辑器文件锁，exFAT/NTFS 行为后续分别实测。
4. **采用状态拆分不能绕过仓库规则。** 正式运行采用仍要求 Git merge/PR 实际合并，且实际源码与发行产物对应；不把 URL/运行指针切换算合入。不自动 stash/commit 或整目录暂存。
5. **保护环境不是本地 localhost 预览。** Windows Sandbox 首版关闭网络，实际操作在 guest 候选窗口；稳定端接收关联场景。未实现远程嵌入前不能冒称无缝嵌入通过。
6. **guest 数据不是宿主授权。** 候选不得在 mailbox 中创建主消息/确认；ArtifactRef 来源由接收端解析，不能自报提升可信等级。
7. **字段脱敏不等于像素脱敏。** 运行配置不原样导出；图片遮罩失败默认不外发，外部模型调用需要数据披露授权。
8. **保护等级必须诚实。** 只读确认 F: 为 exFAT、C: 为 NTFS，并核对官方 ACL 对照；本地受管不被称为强隔离。Windows Sandbox 是选定后端，尚无本机可运行证明。
