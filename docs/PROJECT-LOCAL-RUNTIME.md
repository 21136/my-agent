# 项目内运行目录与版本存储

## 运行目录

项目内模式的初始固定位置是 `F:\my-agent-main\.worktrees\sandbox\.managed-runtime\<安装 UUID>`。源码仍保持稳定区与 sandbox 分开；运行目录不属于源码、不进版本提交、不供构建清理，也不属于 `artifacts` 测试产物。当前先放在 sandbox 内，避免为了适配路径就改稳定树。不能删除/强制清理/移除整个 sandbox 来回收空间；同步源码不能迁移运行目录。

- 新模式是 **逻辑分离**，不声称 NTFS 私有 ACL 或操作系统安全沙箱。在当前 exFAT 盘上不能把目录命名当作权限隔离。
- 这一路径不保存真实凭据，不迁移、读取或复制旧聊天/密钥。
- 原私有安装模式保留，不会因它的 ACL 检查失败就自动退到项目目录。
- 准备只创建新 UUID 的空目录结构和身份标记，不复制依赖、整套源码或 Node/Electron/Python。

## 当前命令的真实能力

从 `F:\my-agent-main\.worktrees\sandbox` 执行，使用本机 Node：

```powershell
node .\desktop\launcher\managed-cli.mjs --prepare-project F:\my-agent-main F:\my-agent-main\.worktrees\sandbox <UUID>
node .\desktop\launcher\managed-cli.mjs --check-project F:\my-agent-main F:\my-agent-main\.worktrees\sandbox <UUID>
node .\desktop\launcher\managed-cli.mjs --inspect-project F:\my-agent-main F:\my-agent-main\.worktrees\sandbox <UUID>
```

`prepare-project` 只准备新空命名空间；`check-project` 只核对尚未使用的命名空间；`inspect-project` 只读检查真实源码。三者都返回 `ready_for_launch: false`。这些不是运行应用的命令；实际源码采用、发布激活、写入租约和恢复链路还没有因路径适配而自动完成。已有修改的保留/归属审查仍可能让 inspect 退出 3；不允许为变绿而自动 add/stash/merge。

项目自己的采用流程仍是唯一真实合入入口，不以换 URL、手动复制或助手直接 Git 合并替代。旧验收夹具也不能替代正式安装身份。

## 空间如何增长

必须区分三类：
1. 稳定 + sandbox 两套开发区：Git 历史共用，但当前依赖目录分别安装，不能把可变依赖直接合并。
2. 发布版本：现有 E0 机制只复制清单内应用文件，运行时目录通过清单引用/校验，不会每版自动复制一遍全部依赖。但这还不是正式版不可变共享运行时存储，不能据此保证生产版本未来增量。
3. 数据、历史备份和验收产物：随使用/测试增长，不应乘上版本数。未完成兼容性、租约和恢复设计前，也不能为省空间随意删除旧数据或最后可恢复版本。

当前实测数值、扫描命令、分配单元取整误差与每版估算见本轮存储报告。没有自动清理、压缩、链接依赖或迁盘。本轮释放空间为 0。

## 准备中断时

准备过程不是正式发布事务：中途断电、磁盘满或探测失败，可能留下没有完整身份标记的新 UUID 目录。此时检查必须失败；不要把它当作可运行安装，也不要复用或自动删除。保存失败回执和目录，用新的 UUID 重试；如果需要回收失败目录，先确认精确路径、内容与归属，再单独授权处理。当前没有迁移、恢复旧聊天或自动修复运行数据的命令。

## 源码采用审查入口（只读实现，2026-10-24）

本阶段继续补 E1 的只读审查，不进行实际合入/激活。源代码采用仍必须由项目流程执行，助手不直接运行真实 add/commit/stash/merge。旧固定 Host 夹具不能当作正式安装身份。

新增检查会把三种材料分别列出，不能混为“待合入文件”：
- 历史提交触及路径：用于范围追踪，可能含最终已撤销的改动。
- merge-base 到 sandbox HEAD 的净树差异：只是两个 Git 树的元数据差异，**不是合并后稳定树**，也不含尚未提交的工作区代码。
- 两个源码区允许读取路径的原始字节盘点：包括已暂存、工作区和未跟踪源文件的保守比较；不执行 clean filter / textconv，不等同 Git 的换行/过滤器归一化状态，不自动认领改动归属。

受保护路径只做名称/模式/对象身份级别的 Git 元数据处理，不打开工作区中的聊天、密钥、配置存储或运行数据。允许的源码目录盘点也不应让 Git status 或重命名相似度检测间接突破该边界。受保护范围的完整工作区状态仍是未知；原有安全阻断不因新增盘点而消失。

审查报告的摘要只用于重新核对内容，**不是确认回执、执行许可或发布证明**。即使报告能完整显示，execution / readyForMerge / readyForLaunch 仍全部为 false。正式上下文、范围确认后的合入事务/回执、实际合并树重建与溯源、全写路径租约隔离和激活/恢复仍须继续实现。
