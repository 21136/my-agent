# 生产项目协作基线

> 本文是简要产品说明，不覆盖代码中的权限实现，也不是验收报告。运行时事实以当前源码和相应测试为准。

## 项目工作的主要材料

- `PROJECT.md`：目标、范围、非目标与背景。
- `DESIGN.md`（复杂项目可用 `TECH-DESIGN.md`）：方案、关键决策与约束。
- `VERIFY.md`：验证方法、执行结果及证据。验证结果必须如实记录；计划或工具调用本身不代表验证通过。

`TASKS.md` 是旧项目可能遗留的兼容文件；不再把它作为执行队列或普通项目执行的必要制品。旧项目的识别/兼容逻辑可保留相关字段。是否保留、采用其他记录方式由具体项目决定。

## 当前权限判断原则

普通项目不要求先完成固定阶段或任务队列才能工作。每轮根据用户意图、绑定项目与目标路径、操作风险和确认策略决定工具行为：

- 意图区分只读咨询、规划和执行；意图分类不是单独的安全授权。
- 项目绑定与根路径约束限制可触及的文件；越界或缺少必要绑定时由工具策略阻止或要求确认。
- 高风险、外部或不可逆操作依其工具策略请求确认或拒绝。用户确认必须对应实际操作，不能由文档状态推断。
- 计划、阶段和项目文档可以辅助理解，但不替代工具执行层的路径与风险检查。

## 长任务与验证

当前 Goal Runtime 是 P0 的轻量长任务预算/状态骨架，并非旧 runaway 子系统的延续或改名。它不恢复 TASKS、阶段权限、Progress Gate、自动狂奔，也不代表跨进程任务恢复或端到端自动交付已经完成。任务预算、运行状态和实际验证结果应分别理解。
