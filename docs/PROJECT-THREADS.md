## 0. 已决摘要（thinking 锁定）

| ID | 决议 |
|----|------|
| **T1** | **同一项目、同一时刻只有一条活线**在干活；不并行开多条执行中的 agent |
| **T2** | **污染了就砍线重开**；旧线归档后**只读回看**，不在旧线上继续工具回合 |
| **T3** | 砍线入口默认是用户点 **「新开线」**（或等价元命令）；**不**靠模型自判污染后自动砍 |
| **T4** | 开新线后**可跳过交接**，直接空线开聊 |
| **T5** | 若要交接：在**新线上**进行——先问用户要什么，再**只读旧线** + LLM **生成用户需要的话术**；禁止系统静默塞一句简易摘要 |
| **T6** | 磁盘真源仍是项目三件套 / 进度文件；聊天交接是可选加速，不是第二真源 |
| **T7** | **一活线一项目**（修正原 P7「一会话一项目」的「同时仅一条」语义）；一项目可有多条**归档线** |

## 1. 动机

### 1.1 已观察

同一 `project_id` 绑死一条无限变长的 `conversation_id` 时：

- 前面的失败路径（手删 `node_modules`、墙钟误杀、错误归因）污染后续「继续」
- 压缩 / digest 也救不了「模型已把脏路径当成当前事实」
- 用户体感：不是缺算力，是**缺干净上下文**

### 1.2 要什么 / 不要什么

| 要 | 不要（本期） |
|----|----------------|
| 项目内可砍线、可回看 | 多条活线并行跑工具 |
| 用户显式「新开线」 | 系统自动因墙钟/失败砍线 |
| 可选、可问、可生成的交接 | 静默注入固定摘要模板 |
| 急时可跳过交接 | 强制每次砍线都写交接 |

## 2. 概念

### 2.1 活线 vs 归档线

| 词 | 含义 |
|----|------|
| **活线** | 当前 `project_sessions[project_id]` 指向的 `conversation_id`；可正常 tool / confirm |
| **归档线** | 同项目曾用过的旧 `conversation_id`；UI 可打开回看；默认 **Ask / 只读**（见 §5） |
| **新开线** | 创建新 `conversation_id` → 继承项目绑定（`project_id` / `project_root` / `plan_status`）→ 旧活线入档 → 聊天区换成空历史 |

### 2.2 与已有机制的边界

| 机制 | 关系 |
|------|------|
| **跨项目** `项目 切换` | 不变；换的是项目，不是同项目内砍线 |
| **CONTEXT-SWITCH** `session.new` | 同壳「新话题」提案可指向本能力；**项目壳内**以「新开线」为产品名，须保留项目绑定（禁止解绑成裸会话） |
| 元命令 **`新会话`** | 全局语义保留；在 **已绑项目的 project 壳**内，推荐 UI/文案引导为「新开线」（同 T7），避免误以为换项目 |
| **跨会话 read confirm**（IT-17） | 交接读旧线 **复用**；不新开无确认写通道 |

```text
project_sessions[id]     = 活线 conversation_id          （既有，语义不变）
project_thread_archive   = { id: [旧 conversation_id…] } （新增索引）
```

索引形态实现期可微调（list / 带 title·时间的对象数组），但须满足：

1. 任意时刻每个 `project_id` **至多一条**活线  
2. 归档列表可枚举、可打开回看  
3. 旧 `state.json` 无 archive 键时 = 空列表（兼容）

## 3. 用户流程

### 3.1 砍线（主路径）

```text
用户点「新开线」（或元命令）
    │
    ▼
内核：create_new + 复制项目 meta 绑定
    │
    ▼
旧 conversation_id → project_thread_archive[id]
project_sessions[id] → 新 conversation_id
    │
    ▼
session_replaced · 灌空 history · banner「已新开线；旧线可回看」
    │
    ▼
用户可直接发消息干活（T4）
  或先说「根据旧线帮我交接：…」（T5）
```

**确认策略（已决倾向）**：

- 顶栏 / 侧栏按钮「新开线」= **显式动作**，对齐 CONTEXT-SWITCH **X5**（免卡或轻确认即可）  
- 口语「这条线脏了重开」→ 可走 `propose_context_switch` / 等价提案 + 确认卡（与换项目同级心智）

### 3.2 交接（可选 · 新线上）

1. 用户在**新线**说明要什么（例：「只要现在卡在哪、下一步一句」）  
2. 助手只读旧线（`read_file` / `grep` `data/sessions/<old>/…`，走既有跨会话 confirm）  
3. LLM **按用户口径生成话术**（可再改一版），写入本线消息；**不**自动改 `TASKS.md`（除非用户另嘱且过计划门）  
4. 之后正常干活

禁止：

- 砍线瞬间内核塞固定「进度摘要」system 块  
- 在**旧线**上生成交接再切（脏线写交接，T5 否决）

### 3.3 回看归档线

- 侧栏或会话列表：本项目「历史线」  
- 打开 = `session.open` 类只读浏览；**顶栏明确非活线**  
- 「设为活线 / 在此继续」= **另议能力**，本期默认 **不做**（避免一键回到污染上下文）；用户若坚持，须二次确认且文案警告污染风险（开放问题 Q2）

## 4. 协议与 UI（草案）

| 方向 | type / 入口 | 要点 |
|------|-------------|------|
| 入站 | `project.thread.new` 或复用 command | `project_id`（缺省当前） |
| 出站 | 既有 `session.banner` / `session.history` | `session_replaced`；banner 含「已归档上一线」 |
| 出站 | `project.threads`（list） | 活线 + archive 摘要（id、时间、可选 title） |
| UI | 项目顶栏或侧栏 **「新开线」** | 与「新会话」文案区分 |
| UI | 本项目历史线列表 | 回看；标注「归档 · 只读」 |

CLI：`项目 新开线`（名称可议）≡ 按钮。

## 5. Apply 规则

| 步骤 | 规则 |
|------|------|
| 前置 | 当前须有 `project_id`；无项目则提示先立项 / 切换，不假装新开线 |
| 忙时 | 对齐 `project.switch`：助手忙则拒绝或提示先 Stop（回归 S-43 心智） |
| 新建会话 | `create_new`；`meta` 继承 `project_id` / `project_root` / `project_plan_status` 等项目字段 |
| 归档 | 旧 id 写入 `project_thread_archive[project_id]`（去重、新在前或附时间戳） |
| 活线指针 | `record_project_session(project_id, new_id)` |
| 壳指针 | `shell_sessions` / unified project 视角指向新 id（与现 switch 一致） |
| 交接 | **不**在 apply 内自动读旧线或写摘要 |

归档线默认策略：打开回看时 **不**把该 id 写回 `project_sessions`（除非用户明确「恢复为活线」且产品已实现）。
